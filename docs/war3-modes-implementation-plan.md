## 最终交付范围

保留当前四种玩法，再新增三种，最终为七个独立模式。每种新玩法必须具备可观察的核心机制、默认资源下可完成的对局、自己的地图／必要素材、清楚的操作与结算。

- 万象宝石：六系基础宝石、五种配方结果、鉴定五选一、三次付费刷新、两格备选、同系升阶／混合融合、保底、20波。
- 守卫灵姬：一名完整英雄、Q/E/R、经验1–8级、三件装备及强化、两处一次性营地、三类敌人行为、15波。
- 机关军团：六种完整守军、三种进攻雇佣兵、真实双战场、工人／金币／军需／收入、国王、同规则AI、侦察、胜负与平局。首版为单人对战AI。

原808文件、全部旧地图和预览继续保留。新资源独立目录。建造位置连续自由，面板不挤动地图。真人联机另列后续范围，不用AI界面冒充在线对手。

## 实现时的改动边界

- 三种新会话分别封装规则，提供与现有菜单、渲染、研究和操作结果相容的接口；不继续把所有分支塞入一个巨大的step。
- 优先复用现有单位清单、资源装载、音效、自由放置与科技数据。只提取已经被新玩法实际需要的共用逻辑，不先搭建通用游戏框架。
- 宝石增加准备／战斗阶段、候选／库存／配方事务；英雄增加真实可伤害实体与输入控制；军团增加双边状态和同步结算。这三种差异分别验证。
- 费用、概率、伤害、成长和波次集中配置。设计中未定的英雄技能伤害／经验表、宝石五配方强度、军团六兵种／国王数值，在各规则票中补齐并记录，不能实现到一半临时隐藏硬编码。
- 当前四模式的规则和解锁表不回写。每个新模式分别接入本局科技、暂停、倍速、返回菜单、结算和重开。
- 新模式尚未达到可玩状态时，不提供伪装成已完成的正式入口；达到阶段出口后即可独立交付，最终统一检查七模式切换。
- 可以按规则、素材、界面分工并行；同一个main／render／共享样式只由一位集成者合并，避免互相覆盖。已有授权可使用GPT-6.1 Sol中等推理Agent，实际实现时再分派。

## 验证计划

### 开工基线

先运行npm run check和npm test，记录当前四模式的真实结果与原素材摘要；已有52项只是上次完成记录。后续每次按改动范围执行检查，不能把旧检查数量当作新功能通过的证明。

### 宝石阶段出口

- 固定种子复现候选／刷新／保底，概率表每行100%；菜单来回不改变既定候选。
- 普通合成、五配方、库存、容量、科技、出售账本原子执行，失败不扣款不吞材料。
- 至少20个固定种子记录策略与通关／失败原因；种子1／42／2026各记录一条正常经济通关策略。不能筛掉坏种子或改敌人参数冒充平衡。
- 同一随机序列下，不同选留／合成取舍产生不同阵容和可观察战果。
- 默认400金币完成20波，数据和正式图像接入后再放行。

### 英雄阶段出口

- 相同塔阵下，移动英雄、打断、闪避、护盾能分别改变战局；对输入的响应发生在真实英雄实体上。
- 补测碰撞、法力／冷却、死亡复活、经验范围、装备强化、营地奖励一次性及暂停／倍速／菜单冻结。
- 神女归零判败，英雄死亡只复活；可选营地不阻塞主线结算。
- 默认经济、不写入等级／无敌参数，通过15波和三个首领。

### 军团阶段出口

- 玩家／AI同样预算与API，派出的怪物确实出现在对方地图；同样守军改变阵型会改变战损。
- 逐回合核对金币／军需／工人／收入、派兵取消与成交、国王升级、战后复原；收益只结算一次。
- 双方同一步致命判平局；一边暂停、另一边继续模拟属于失败。
- 用固定种子记录正常资源的完整胜负对局；AI不能靠隐藏资源守住基础波，也不能读取未公开订单。
- 侦察显示真实对手状态，界面明确AI对战。

### 综合交付与人工体验

自动检查包括旧四模式回归、七会话隔离、类型／语法、资源引用、原808文件哈希与旧地图保存、各自完整对局、非法操作和关键结束边界。正式画面要查看实际渲染结果，独立复核核心差异，修复问题后再交付。

浏览器完整操作、实际声音和主观难度继续由用户处理。当前人工票11仍覆盖已交付四模式；三种新模式完成后再追加它们的实际验收结果，未实施前不提前勾选。
