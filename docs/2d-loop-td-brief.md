## 2. 成品定位

制作一款以电脑横屏、鼠标操作为主的单人浏览器塔防游戏。科技防御单位对抗东方玄幻敌人，采用现有素材的潮玩卡通外观，以固定视角展示战场。

“2D”指平面上的移动、布塔和战斗规则；单位继续使用现有透明图片，保留其透视与体积感。相关取舍记录在 ADR-0001。

## 3. 素材保护与新文件边界

- `outputs/` 和 `work/` 全部作为只读原始资料保留，包括图片、预览页、清单、说明、脚本、源图和备份。
- 新游戏、新地图素材、游戏配置、音效及运行说明均写入独立目录。建议游戏目录为 `game/`，新地图资产放在 `game/assets/maps/`；这是拟采用的目录安排，当前尚未创建。
- 游戏通过只读引用使用原图。需要派生尺寸、图集或打包副本时，仅输出到新游戏目录，保留原文件与原路径。
- 地图和游戏需要的新资源使用独立文件名与清单，不回写原 `outputs/manifest.json`。
- 原素材存在的方向漂移等问题以原检查报告为准；后续如需修图，另存为派生资源。

## 4. 现有素材与缺口

素材规模以 `outputs/manifest.json` 为准：12 种科技防御单位、12 种东方玄幻敌人，24 个单位均有八方向图，共 192 张方向 PNG；另有 6 个道具、6 张特效静帧。

原素材提供了画布、方向、锚点和比例信息。接入时应遵循原规范，保持同一单位跨方向的比例和地面落点稳定。除清单明确支持分层的单位外，使用完整方向图。

当前没有完整地图、音频或连续动作动画。新增地图属于正式交付；音效需要补齐；现有特效是静帧，战斗动效需要另外实现。仅有素材预览页，没有已完成的塔防游戏。

## 5. 核心玩法

| 项目 | 目标行为 |
| --- | --- |
| 环路 | 敌人沿闭合道路反复行进；路线可采用适合画面与塔位布局的闭合形状 |
| 出怪 | 按时间节奏持续投入波次；旧怪尚未清除时，新波次仍可到来 |
| 失败 | 场上存活怪物数量达到容怪上限即失败；绕完一圈本身不扣基地生命 |
| 经济 | 击杀敌人获得金币，用于建造和升级；出售提供回收能力 |
| 操作 | 选择固定塔位，建造、选择已有塔、查看属性、升级和出售；攻击自动进行 |
| 防御组合 | 让现有防御单位形成有区别的输出、控制或辅助用途，具体分工和数值在开发中落实 |
| 常规关卡 | 建议 20 波，每 5 波一个 Boss；具体节奏与数值仍可调优 |
| 通关与无尽 | 清除常规关卡的敌人后提供通关结算，并可选择继续无尽挑战 |

本版按单人核心玩法推进。多人合作、手动操作英雄，以及主塔养成、木材、装备、随机抽塔等扩展体系不在当前范围内。

## 6. 新增地图素材

新增地图是本版必须完成的画面交付，不能只接入单位而遗漏战场环境。

| 素材项 | 交付要求 |
| --- | --- |
| 地面底图 | 与现有单位的固定视角、体积感、描边和左上光照协调，单位轮廓清晰 |
| 闭合道路 | 道路连续，转弯自然，画面与实际怪物路线一致，便于看懂行进方向 |
| 出怪入口 | 能识别敌人进入环路的位置，与环路衔接 |
| 建塔底座 | 固定塔位清晰，空位、选中和已建造状态可辨，尺寸适合单位落点 |
| 环境装饰 | 结合原有道具，补充必要的植被、岩石或边界装饰，避开主要操作区和战斗信息 |

地图制作顺序：先安排道路、入口、塔位和单位比例，验证射程覆盖与遮挡关系，再制作正式地面与装饰画面，最后将原有单位放入场景检查协调性。

地图画布尺寸、塔位数量和具体地貌尚未确定，开工后依据电脑横屏画面与实际素材比例确定。地图成图、派生文件和制作记录均遵守第 3 节的文件边界。
